**Дата:** 2 марта 2026
**Изучены документы:** course_structure_v2.md, teaching_vision_v4.md, dialog_context.md, AI. Webinar 1–4

## 1. ОБЩАЯ ОЦЕНКА

Курс построен вокруг сильной идеи: сквозной проект (лендинг → деплой → кастомизация → автоматизация), каждый вебинар даёт видимый результат, есть «wow-моменты». Педагогическая философия (20/80, Junior Partner, антиинфоцыганство) последовательно прослеживается во всех вебинарах.

Однако при сведении всех документов вместе выявляется ряд рассинхронизаций, логических разрывов и зон риска, которые нужно закрыть до запуска.

## 2. КРИТИЧЕСКИЕ ПРОБЛЕМЫ (блокеры)

### 2.1. dialog_context.md рассинхронизирован с реальными вебинарами

**Проблема:** dialog_context описывает Вебинар 2 так, будто в нём есть system prompts, MCP, скилы, агенты и IDE (по ~15 мин на каждый). Но в реальном документе Вебинар 2 — это чисто инфраструктурный: VPS + OpenClaw + Telegram + деплой + архитектурная теория. Все перечисленные темы на самом деле в Вебинаре 3.

Более того, в dialog_context описание Вебинара 3 — это копипаста описания Вебинара 2 (те же темы, те же тайминги). Это значит, что dialog_context **не отражает актуальное состояние курса**.

**Риск:** Если этот файл используется для переноса контекста в новые чаты с ИИ, все последующие итерации будут строиться на неверной основе.

**Рекомендация:** Обновить dialog_context.md, чтобы точно отражать содержимое реальных вебинаров 1–4. Или пометить его как deprecated и создать новый context-файл.

---

### 2.2. course_structure_v2.md помечен [outdated], но является каноническим

**Проблема:** Документ помечен [outdated] в заголовке, но именно на него ссылаются Вебинар 3 и Вебинар 4 как на «связанный документ». Нет актуальной версии course_structure.

**Рекомендация:** Создать course_structure_v3.md, который станет единственным источником истины. Убрать пометку outdated из старого или удалить его.

---

### 2.3. Тайминг Вебинара 1 = 60 мин, а Вебинаров 3–4 = 75 мин — нестыковка с форматом

**Проблема:** course_structure заявляет «4 вебинара × 1 час». Но Вебинар 3 и 4 сами указывают формат ~75 мин. При этом Вебинар 3 даже при 75 мин не укладывается: 7+10+15+(7 виджет)+15+8+10+7 = ~79 мин.

**Рекомендация:** Либо честно обновить формат до «60–90 мин» во всех документах, либо сократить контент В3. Конкретно для В3 кандидаты на сокращение: секция IDE (п.6, ~10 мин) — можно вынести в материалы для самостоятельного изучения.

## 3. ЛОГИЧЕСКИЕ РАЗРЫВЫ В ПОСЛЕДОВАТЕЛЬНОСТИ

### 3.1. Студент неделю работает с OpenClaw БЕЗ system prompt

**Ситуация:** В2 заканчивается деплоем OpenClaw + Telegram-бот. Между В2 и В3 — целая неделя. System prompts, MCP и скилы появляются только в В3.

**Проблема:** Студент неделю пользуется агентом с дефолтным поведением. Первое впечатление от инструмента — «он какой-то тупой» / «он отвечает не так, как я хочу». Это демотивирует, особенно для джуниоров.

**Варианты решения:**
- **Вариант А:** В ДЗ после В2 дать минимальный шаблон system prompt + инструкцию «настрой своего агента». Тогда В3 углубляет то, что студент уже попробовал.
- **Вариант Б:** Вынести system prompt в В2 (добавить 10–15 мин), а из В3 убрать это в пользу более глубокого погружения в MCP + скилы.
- **Вариант В (минимальный):** В предварительной рассылке к В2 включить готовый system prompt, который автоматически ставится при установке OpenClaw. Студент не пишет его сам — но агент уже ведёт себя адекватно.

---

### 3.2. Виджеты: обещаны в ДЗ В2, но появляются только в В3

**Ситуация:** course_structure_v2 говорит: ДЗ после В2 = «кастомизация профайла виджетами через OpenClaw». Но сам документ Вебинара 2 говорит ДЗ = «добавить одно изменение + залить в GitHub». Никаких виджетов. Виджеты впервые появляются в В3 (живой виджет через MCP).

**Проблема:** Рассинхрон между course_structure и реальными вебинарами. Студент не может сделать виджеты после В2, потому что ещё не знает MCP.

**Рекомендация:** Обновить course_structure: виджеты — результат В3, не В2. ДЗ В2 = простая кастомизация лендинга (верстка/стиль/контент через промпты).

---

### 3.3. «Архитектура IT-приложения» — дублирование между В2 и В3

**Ситуация:**
- В2, секция 3: «Как устроено IT-приложение: фронтенд → бэкенд → БД → API → VPS»
- В3, секция 1: «Что такое OpenClaw — что это, из чего состоит»

**Проблема:** Частичное пересечение, но без явной связи. Студент может воспринять как повторение.

**Рекомендация:** В2 — общая картина («из чего состоит любое IT-приложение»). В3 — «а вот OpenClaw — конкретный пример такого приложения, давайте разберём его по той же схеме». Явно сослаться на схему из В2.

## 4. ПРОБЕЛЫ В СОДЕРЖАНИИ

### 4.1. Фреймворк «4Д» — используется, но не определён

В1 разбирает промпт через «фреймворк 4Д». Ни один документ не описывает, что это за фреймворк. Нужна либо ссылка, либо расшифровка в материалах В1.

### 4.2. ~~API — заявлен в teaching_vision~~ → УДАЛЕНО

*Устаревшая информация в teaching_vision (Блок 2 — API). Не актуально для текущей структуры курса. Рекомендация: вычистить из teaching_vision, чтобы не путал при новых итерациях.*

### 4.3. Debugging-мышление — ценность без модуля

teaching_vision выделяет debugging как ключевой принцип. Но ни один вебинар не содержит явного блока «что делать, когда не работает». Студенты-джуниоры гарантированно столкнутся с ошибками при деплое (В2) и настройке MCP (В3).

**Рекомендация:** Хотя бы в ДЗ добавить формат «отчёт: что сработало, что нет, почему» (это уже есть в рисках course_structure — стоит явно включить в требования ДЗ для В2 и В3).

### 4.4. CLAUDE.md (system prompt для Claude Code) — нигде не упоминается

Файл CLAUDE.md из Google Drive предполагает, что это учебный артефакт. Но ни один вебинар не объясняет студентам, что такое CLAUDE.md и как его использовать для настройки Claude Code.

**Рекомендация:** Если CLAUDE.md — часть курса, добавить короткую секцию в В1 или В3 (где обсуждаются system prompts). Если это внутренний документ — не проблема.

## 6. ЧТО РАБОТАЕТ ХОРОШО

- **Нарастающая автономия студента:** В1 (следуй промпту) → В2 (разверни сам) → В3 (настрой под себя) → В4 (автоматизируй)
- **Wow-моменты в каждом вебинаре:** лендинг за 15 мин, сайт в интернете, живые данные на странице, агент работает пока спишь
- **Telegram-опрос перед В3** — элегантное решение для выбора MCP, вовлекает студентов
- **Human-in-the-loop в В4** — правильный подход к безопасности автоматизаций
- **В4 — самый проработанный документ:** чёткая структура, конкретные кейсы, реалистичные тайминги
- **Сквозной проект** — лендинг как «позвоночник» курса, который эволюционирует
